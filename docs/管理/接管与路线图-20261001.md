### 1.5 失败清单

**本地 `clean build` / `check`：0 失败。**

**GitHub Actions 历史失败（此为接管时最重要的风险信号）**：

- CI 最近 30 次运行：**16 绿 / 14 红**；最后一次绿是 **2026-07-12**，此后全红（2026-10-01 查询）。
- 当前失败模式（run [35454581886](https://github.com/chaineasy-ai/alice-agent/actions/runs/35454581886)，2026-09-19）：
  - macOS、Windows 的 build 通过；
  - **ubuntu build 在 `Run all tests` 失败** → `:alice-agent-runtime:test FAILED`；
  - `native-image` 因 `needs: build` 失败被整体跳过（三平台 native 验证实际停摆）。
- 失败用例（CI 日志原文）：

  ```
  RoundEventPublisher — 回放不丢帧（stress） > 100 轮（立即订阅）：帧序列恒为 [SUMMARY, DONE] FAILED
      org.spockframework.runtime.UnallowedExceptionThrownError at RoundEventPublisherStressSpec.groovy:36
          Caused by: org.cland.alice.agent.proto.port.DispatcherBusyException at RoundEventPublisherStressSpec.groovy:30
  > Task :alice-agent-runtime:test FAILED
  46 tests completed, 1 failed
  ```

- **根因（已定位）**：`AgentHost.round()` 的收尾顺序是 `emit(DONE) → pub.complete() → roundActive.set(false)`。订阅者 `onComplete` 释放 latch 后测试立刻发起下一轮 `dispatch()`，若后台线程尚未执行到 `roundActive.set(false)`，CAS 失败抛 `DispatcherBusyException`。本地负载低时窗口极小（稳定通过），CI runner 负载高时被放大（偶发必现）。
- **修复建议（约 0.5 人日，建议作为 M3-0 先行）**：
  1. 调整 `AgentHost.round()` finally 内顺序为 `emit(DONE) → roundActive.set(false) → pub.complete()`（先放锁再收口，保证订阅者观察到 DONE 时锁已释放）；
  2. 压测用例侧同时加固：下一轮 `dispatch` 前轮询 `health().roundActive()==false`（或对 `DispatcherBusyException` 做一次有界重试），避免测试对实现顺序过强耦合。
- 另注：2026-09-09 及更早的运行三平台均红，对应 TODO-kernel-r0 记录的测试债（planner 44/93、guardrail 37/67 失败、bootstrap 真实 LLM 依赖），该批问题已于 2026-09-10 在代码侧修复；此后 CI 剩余红点即上述 runtime 竞态。


## 3. T3 Roadmap 固化（M1–M3）

> 来源：`todos/TODO-kernel-r0.md` §1–§4 + `specs/001..003` + 本档盘点。顺序即依赖顺序。

### M1 图内核收口（Graph Kernel Close-out）

- **目标**：图内核在默认关闭状态下补齐生产级执行语义，为 M2 翻转准备能力底座。
- **切片队列**（建议顺序）：
  1. **S1 取消语义进循环**（#174，本窗口，§4）
  2. S2 WAL/Checkpoint 接入图内核：Ledger trace/产物快照 → Checkpoint；恢复 = 回放 + 重路由
  3. S3 verifyPost(g) 适配：GuardrailVerificatorAdapter → GatePolicy（D8 维持原语义）
  4. S4 多级预算（D12）：goal 效果数/嵌套深度/token 注解定标（替换 maxIterations/maxMicroDepth 单计数）
  5. S5 HITL gate：HitlChannel 挂起/恢复/超时接入骨架
  6. S6 D11 LedgerScopeValidator：槽位写权限校验 + 结构槽位写点运行时断言
  7. S7 子 agent 同契约递归：SessionRequest/Result 图嵌套接线（依赖 003 收口）
  8. S8 artifact 多产物语义（低优先级，可后置）
- **出口判据（一句话）**：`graphKernelEnabled=true` 时，标准骨架会话具备"**取消可中断、WAL 可恢复、门可拦截、预算可熔断**"的全生命周期，且每个切片有 Spock 证据、`./gradlew check` 全绿。
- **风险**：core-agent 覆盖阈值；WAL 格式兼容（legacy 恢复路径同仓共存，须做语义对照测试）。

### M2 facade 契约迁移（Kernel Runtime Swap，specs/004）

- **目标**：双运行时（legacy AgentExecutor / 图内核）收敛为单一路径，默认翻转，门面全面走图语义。
- **内容**（TODO-kernel-r0 §1）：
  1. `specs/004-kernel-runtime-swap` 建档（spec/plan/tasks/contracts/checklists）
  2. `ask/askAsync/run` 业务门面迁移：AgentContext → SessionRequest/SessionResult（消费点审计）
  3. facade 消费迁移：ExecutionCoordinator / JLineChatSession / AliceTuiLauncher 走事件桥
  4. executor 语义测试基线迁移（AgentPpaoLoopSpec 等重定到图语义或显式标注 legacy-only）
  5. legacy AgentExecutor 保留策略定稿（删除 / 降为子 agent / 恢复路径专用）
  6. KernelDelegates 收敛 + 迁移指南文档
- **出口判据（一句话）**：`AgentConfig.graphKernelEnabled` **默认 true** 后，facade 全链路经 SessionRequest/Result + 内核事件桥运行，legacy 语义测试完成重定，`./gradlew check` 全绿且 legacy AgentExecutor 去留已定稿文档化。
- **依赖**：M1 完成（能力齐备才允许翻转）；specs/004 建档可与 M1 后期并行。

### M3 生产可用（Production Readiness）

- **目标**：从"本地能跑"到"可部署、可观测、可回归"。
- **工作包**：
  - **M3-0 门禁修复（先行）**：修 runtime 竞态（§1.5）；CI 从 `assemble+test` 升级为 `check + spotlessCheck`；native-image 不再因 build 红被整体跳过。
  - M3-1 发布形态：版本 tag/Release 流程；三平台 JVM dist + native image 验证回归；安装/升级文档。
  - M3-2 可观测：`sessionId` 贯穿 WAL/事件/Langfuse（方案已在 `docs/audit/`）；内核实事件埋点（decision/effect/gate）。
  - M3-3 运维对接：pi 三层通信同构接口（`docs/pi-integration/`）落地；健康检查/常驻 worker 说明。
- **出口判据（一句话）**：main 分支 CI **连续 7 天绿**、存在一个可回溯 tag 及三平台可下载制品、`sessionId` 可跨 WAL/事件溯源、且门禁（check+覆盖率+spotless）成为合并强制条件。
- **并行性**：M3-0 可与 M1 并行（互不冲突）；M3-1 依赖语义相对稳定（M1 中期后）；M3-2 可随时启动。

## 5. T5 治理建议（成本/风险；**未擅自迁移，未动远端设置**）

### ① 是否迁 Gitea 私有

**现状（2026-10-01 实查）**：GitHub `chaineasy-ai/alice-agent` 为 **public**；0 star / 0 fork / 0 open issue；仓库 3.2MB；无 tag/Release；贡献者 2 人（hack0303 186 提交、charlie 47 提交）。Gitea `base/cland-crawler` 已是本单与协作流程的问题管理入口。

**选项对比**：

| 选项 | 成本 | 风险 | 适用前提 |
|------|------|------|----------|
| A. 整体迁 Gitea 私有 | 迁移 ~0.5d（`git push --mirror`）；CI 重搭 **1–2d**（Gitea Actions runner 或 Jenkins）；外部引用/徽章清理 0.5d | Gitea 单点（SQLite）；CI 生态弱于 GitHub；native-image 三平台 runner 需自备 | **代码含敏感资产**且确定不再公开 |
| B. 双轨（推荐过渡） | 0d 迁移（Gitea 已承载流程）；可选 Gitea 建只读镜像 0.5d | 代码仍在公网；需明确"哪边是权威" | 现阶段：研究/备选线，流程在 Gitea |
| C. 保持现状（GitHub 主仓） | 0d | 数据私有化诉求不满足 | 目标形态为开源产品/对外协作 |

**建议**：**本窗口不动**。若 D1 定为"内核产品化且涉密" → 选 A，迁移应在 **CI 修复之后**（否则把红的 CI 一起搬过去）；若为"研究线/pi 备选" → 选 B，Gitea 作流程与 issue 主入口，GitHub 仅作代码镜像/公开窗口。任何迁移需 Owner 明确批准后另立工单。

### ② CI 现状（GitHub Actions）

**事实**：

- 最近 30 次 CI：16 绿 / 14 红；**2026-07-12 后全红**；当前唯一根因 = `alice-agent-runtime` 压测竞态（§1.5），本地稳定通过。
- 现行 CI 只跑 `./gradlew assemble` + `./gradlew test`：**不跑** `check`（覆盖率）、`spotlessCheck`、hole tests、e2e。
- `native-image` job `needs: build`，build 一红即三平台 native 验证全部跳过。
- Actions 版本提示：`actions/checkout@v4`、`setup-java@v4` 等被标记 Node 20 弃用告警（非失败原因）。

**建议**：

1. **M3-0（0.5d）**：按 §1.5 修复 `AgentHost` 收尾顺序并加固压测用例；恢复绿色基线。
2. **CI 命令升级**：`./gradlew check spotlessCheck --no-daemon`（check 已含 test + 覆盖率校验），使"本地纪律 = CI 纪律"；建议加 `--stacktrace` 便于排障。成本 ~0.5d（需处理 native job 时长）。
3. **native-image**：拆为独立 workflow 或允许 `continue-on-error` 先观测，避免被 build 失败连坐；三平台 runner 成本高，可改 weekly/nightly。成本 1d。
4. **e2e**：不阻塞每 PR；用本地 mock（httpbin / 本机 Gemma4）在 nightly 跑冒烟。成本 1–2d（属 M3-3/M3-2）。

### ③ 门禁（Spock / 覆盖率 / 分层）

**现状**：

- 本地 `check` = 编译 + Spotless（编译期 `spotlessApply`）+ Spock 单测 + JaCoCo 阈值（core-agent 40/25；其余 80/70；cli/tui 跳过）→ 本地门禁**强**。
- 分层只靠 `module-info.java`（JPMS requires/exports，编译期）+ build.gradle 依赖声明，**无架构断言**（如 ArchUnit）。
- 9 个 HoleTest（模块边界探针）**不在 check**；e2e 不在 CI。

**建议**：

| 项 | 建议 | 成本/风险 |
|----|------|-----------|
| Spock 单测 | 保持；M1 每切片出口强制新增用例 | 0（纪律） |
| 覆盖率 | 保持现有阈值；core-agent 随内核新增盯分支余量（44.2% vs 25%）；可考虑 M2 翻转后重定 40→更高 | 低 |
| 分层 | 新增依赖方向断言（ArchUnit 或 Gradle 校验脚本），至少钉住"facade 不反向依赖 runtime/core 内部" | 1d，中低风险 |
| Hole/冒烟 | 建议 nightly 或发布前跑 `runHoleTest`；不阻塞日常 PR | 0.5d |
| CI 强制 | ② 落地后成为合并条件（branch protection 由 Owner/管理员操作） | 需远端设置授权（本单未动） |
