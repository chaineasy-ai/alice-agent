### 1.2 一轮一锁（会话宿主语义）

- `AgentHost.round()` 用 `roundActive.compareAndSet(false,true)` 保证**同一时刻只允许一轮 prompt**；忙时抛 `DispatcherBusyException`（见 `AgentHost.java:109`）。
- **为何用 CAS 而非 `ReentrantLock`**：轮次在**独立虚拟线程**上收口（`AgentHost.java:105` 起 `Thread.ofVirtual().name("alice-round-"+traceId)`），而 `ReentrantLock` 要求「谁加锁谁解锁」且对同线程可重入 —— 实测有两坑（见 #461）。
- **关键收口点**：`finally` 内 `roundActive.set(false)`。事件订阅（`engine.events().subscribe(listener)`）必须在 `try` 内，订阅失败也要能收口，否则 `roundActive` 永不释放（卡死 busy）。当前实现满足。
- 图内核与宿主的衔接：宿主经 `EngineEvents`（`events()`）订阅内核事件；图内核 `events()` 返回 `KernelEventStream`，由 `traceBridge()` 把解释器埋点翻译为 thought/action/observe。

### 1.3 actor 收敛（`LlmActorBrain`）

- **输入**（② Assemble 最简形态）：原始 `<task>` + `<goal>`（P7 目标上下文）+ 最近 8 条 `<observations>`（P1a 观测历史，供模型判断信息是否已足够）+ 收口指令。
- **决策映射**：`TOOL_CALLS → act`（同批多个 tool_calls 排队逐次消费）；`CONTENT → finish-goal`（不终结会话，goal 级判据提交）；`FAILED/TRUNCATED → 抛异常`（内核收口为 FAILED，brain 不含业务兜底）。
- **强制收口**（P1b）：连续工具轮次 `MAX_TOOL_ROUNDS=6` 达阈后，`inferWithoutTools(...)` 要求直接作答；失败回退最近观测。避免「多轮工具后不收敛」（#316 根因）。

### 1.4 虚拟线程执行（`GraphSessionKernel.execute`）

- `#314` 前：用 `vertx.executeBlocking` 承载**整段多步会话** → 长期占用 Vert.x worker 并触发 `BlockedThreadChecker`；且 `TextLlmPipeline` 传输为同步 `java.net.http`，不需 Vert.x 上下文。
- 现状：`Thread.ofVirtual().name("graph-kernel-"+sessionId).start(() -> runSync(...))`，经 `Promise` 桥回 `Future`；异常也收敛为 `FAILED` outcome，保证 `state()/lastOutcome` 单一真相。
- 实测：on 路径 `.md 计数`任务 35s 内完成，无 `BlockedThreadChecker`/`Vertx Thread blocked` 日志。

### 1.5 步数预算

- `DEFAULT_MAX_STEPS = 200`（`#314` 从 10000 收紧）；`maxStepsOf()` 支持 `maxSteps`（现代）与 `maxIterations`（legacy，×100）两种 option 键；预算为图遍历步数单一来源（P4）。

### 1.6 系统提示注入

- `GraphSessionKernel` 构造器对 `actorSystemPrompt` 做 `Objects.requireNonNull`（`#316` 装配 fail-fast）。
- 默认装配（`Agent.graphKernel()`）注入 `PromptManager.buildMicroLoopSystemPrompt()` —— 优先 `~/.alice/prompts/micro_loop.ftl`，否则 classpath 模板 + `~/.alice/rules/` 规则段。
- 修复前 `actorSystemPrompt=null` 导致 actor 15 次全 `TOOL_CALLS`/0 finish → answer 空（#316 根因）。

### 1.7 开关与执行路径切换

- **口径**：CLI `--graph-kernel[=on|off]` > 配置 `graphKernel.enabled`（兼容扁平键）> 默认 **on**。
- 生效值/来源/执行标注打印在启动横幅：`[loop] maxIterations=10 · graphKernel=true (source=cli, exec=graph) · skipMicro=false`。
- **执行路径**：`Agent.askAsync()` → `config.graphKernelEnabled()` 为真走 `askViaGraphKernel()`（`SessionRequest → GraphSessionKernel.execute → SessionResult → AgentContext`），否则走 legacy `executor.execute()`。`kernel()/events()` 同样按开关分派。

### 1.8 调用链（CLI 一次任务）

```
AliceCliLauncher
  → initializeModelProvider()（~/.alice/model.json 的 default_model）
  → ExecutionCoordinator.execute()
      ├─ 解析 graphKernel 生效值/来源（CLI > config > default）
      ├─ AgentConfig.builder().graphKernelEnabled(...)
      ├─ Agent.withWal/withGuardrail (+ graphKernel 时 withPlannerService)
      ├─ StartupBanner.print(... exec=graph|legacy)
      ├─ agent.askAsync(task)
      │     └─ graphKernel ? askViaGraphKernel → GraphSessionKernel.execute (虚拟线程 runSync)
      │                    : executor.execute (legacy PPAO)
      └─ renderer.renderFinal(answer) → exit 0
```
