# ADR-0001 规划为执行流内的双循环

## 1. 背景与意图（Owner 2026-10-24 原话口径）

- **设计意图**：**任务步骤拆解——大目标拆小目标**（不是"在工具列表里挑一个下一步"）。
- **实现参考**：双循环（dual loop）架构。主流实现（Plan-and-Execute 的 replanner、Reflexion、Voyager、ADaPT、经典 BDI/HTN、System1/2 借用）的共同点：
  - **内循环**：逐步执行（快）；
  - **外循环**：重新规划/分解（慢）；
  - 两者由**执行结果**耦合——外循环的触发信号是"结果事件"，**没有任何一个主流实现按"输入长度/关键词"决定要不要深思**。

## 2. 现状与偏离（实读，2026-10-24）

| # | 现状 | 偏离 |
|---|---|---|
| D1 | `StrategySelector.defaultComplexityCheck()` 用 `prompt.length() > 200` / 关键词 / 有 feedback 决定快慢 | **入口按输入特征路由**，主流架构里不存在这种形态；"话多 ≠ 任务复杂" |
| D2 | 外循环存在（`StandardSkeleton` VP 拦截 ⇒ `ledger.feedback` ⇒ `PlannerGoalBrain` 再规划） | **触发面只有 1 种**（guardrail 拒绝），缺 step 失败 / 前置不满足 / 观测偏差 / 依赖失效 / 新信息 |
| D3 | 内循环的"下一步"由 `Inferencer`/LLM 直接决定并执行 | **内循环没走 planner**；planner 只在外循环被调用 ⇒ 看起来"只在入口用一次" |
| D4 | 慢路径产出"一份 Plan" | 应为**目标 DAG 的局部 patch**（否则丢已完成步骤 + 成本爆炸） |
| D5 | `mcts.md` Overview 说 "decompose into sub-objectives"，State 表说 child = "single executable tool" | **同文档两种粒度**，实现只能挑最省事的那种 ⇒ 慢路径空转（评分用 `prompt.length()`，候选 state 全相同） |

## 3. 决策

**规划 = 执行流内的双循环**：

```
Goal
  │
  ▼
外循环（慢·事件驱动）：分解 / 局部重分解 ──→ 目标 DAG
  │                                          （节点=子目标，叶=可执行步骤 + 验收条件）
  ▼
内循环（快·每步）：
   ① 取下一个可执行步骤（满足依赖、前置条件成立）
   ② 选工具 + 填参数（规则型前置检查）
   ③ 执行 Act
   ④ 真实观测 Observe
   ⑤ Post-gate 校验 → 偏差判定
        ├ 通过 & 无偏差 ⇒ 回到 ①（继续下一可执行步骤）
        └ 触发（见 §4 六个信号）⇒ 回到外循环：**只重分解受影响子树**
```

配套决策：

- **D-a**：`StrategySelector` 语义改为 **`TriggerPolicy`**：输入 = 结果事件 + DAG 状态，**不再读 prompt 特征**；
- **D-b**：`mcts.md` 的定位从"核心算法"改为 **L3 选择器（条件启用）**：仅当"同一子目标存在多个互斥方案、且方案本身是一串步骤"时启用；前提是存在**廉价转移模型**与**可机判收益**；
- **D-c**：`ObservationModel` 从"可选预测"升级为**执行流必需件**：它提供步骤的 `precondition / effect` 推演，用于 ②（能不能执行）与 ⑤（偏差有没有发生）。规则型（工具语义/文件系统/权限）优先，模型型只做兜底且**不得作为放行依据**；
- **D-d**：MCTS 未满足启用前提时 **fail-closed**：不得运行、不得输出 `bestAction/bestAvgReward` 当作结论。

## 4. 外循环的触发面（最小集，缺一即视为半瘫）

| # | 触发信号 | 判据（可判） |
|---|---|---|
| T1 | **步骤执行失败** | 工具返回错误 / 超时 / 非 0 退出 |
| T2 | **前置条件不满足** | `precondition`（规则型推演）为假时**在执行前**即触发，而非执行后补救 |
| T3 | **Post-gate 拒绝** | guardrail 校验不通过（现状唯一已实现） |
| T4 | **观测偏差超阈** | `predicted` 与 `actual` 的差异超过阈值（阈值须是数字，不接受"感觉不对"） |
| T5 | **依赖失效** | 上游步骤未产出下游所需产物（DAG 边断） |
| T6 | **新信息改变目标** | 人工插话 / 新需求进入，使得某子目标的验收条件不再成立 |

## 5. 判据（可红，用于验收）

- **K1 外层触发**：把 T1/T2/T4/T5/T6 任一信号注入后，必须观察到一次"局部重分解"，且 **DAG 只改受影响子树**（其余子树节点 id 不变 ⇒ 可判）。注入后无重分解 ⇒ FAIL。
- **K2 内层归属**：每个被执行的动作必须能追溯到"planner 输出的某一步"（step id / goal ref 可查）；追溯不到 ⇒ 说明内循环绕过了 planner ⇒ FAIL。
- **K3 无输入特征路由**：`grep` 不到"按 prompt 长度/关键词决定策略"的分支（或该分支被 `TriggerPolicy` 取代）⇒ PASS。
- **K4 分解质量**：叶节点 100% 绑定到"存在的工具 + 合法参数 + 明确验收条件"；三者缺一 ⇒ FAIL。
- **K5 DAG 无环**：存在环 ⇒ FAIL。
- **K6 MCTS 启用前提**：无廉价转移模型 / 无收益定义 ⇒ 不得启用；启用时必须打印所用 simulator 与奖励定义来源 ⇒ 缺打印 ⇒ FAIL。

## 6. 放弃的做法（明确不做）

- ❌ 入口按 `prompt` 长度/关键词选快慢；
- ❌ 用 LLM 当 MCTS 的 simulator（每次模拟一次模型调用 ⇒ 慢路径比快路径贵 N 倍且幻觉放大）；
- ❌ 慢路径产出"整份新 Plan"覆盖旧计划（丢已完成成果）；
- ❌ 无验收条件的子目标（无法判完成 ⇒ 无法判重分解时机）。

## 7. 后果

**正面**：慢循环有了真实的触发面；planner 在每步都有位置；MCTS 被放回它擅长的层（方案竞争），不再是空转主体；"能答≠能改"这类入口一次性决策的病根被移除。

**代价**：需要实现 `precondition/effect` 规则表（工具语义）——这是**真资产也是真成本**；`Plan` 语义需从"一次性计划"改为"DAG + patch"；`TriggerPolicy` 替换 `StrategySelector` 属破坏性改动，需同步改 hole/unit 测试。

**退出/复核条件**：若长期无"同层互斥方案"证据 ⇒ 连同 MCTS 一并移除，只保留 分解 + 规则型前置推演（成本更低）。
