# JLine 3 三层TUI架构 v2.0 工程设计文档
## 前言
为让这套高性价比、极致稳定的 JLine 3 三层架构在**工程落地**与**黑客美学**层面达到最优表现，方案完整保留原有三大底层约束：**绝对边界固定**、**无画面抖动**、**低开销增量重绘**，同时在视觉表现、终端空间利用率上完成全方位迭代升级。

本次重构三大核心改造点：
1. 引入 **ANSI 256/TrueColor 视觉分层渲染**
2. 实现 **动态视口截断机制**
3. 针对 `/model` 补全弹窗边界溢出问题，构建完整工程级边界防御体系

## 🛠 架构与工程实现重设计（Tactical Blueprint）
为稳定落地上述无闪烁、无溢出TUI交互，底层 `alice-facade-tui` 模块需严格遵循以下工程实现方案。

### 1. 视口与边界数学防御策略
核心目标：防止补全菜单 `AUTO_MENU` 展开时挤压、顶出底部状态栏，重写原生 JLine `LineReader` 高度控制逻辑。

#### 变量定义
- $H_{total}$：终端可视区域总高度
- $H_{log}$：上方日志面板分配高度
- $H_{input\_max}$：中间输入区最大可用高度

#### 高度约束公式
$$H_{log} = H_{total} - H_{input\_max} - 3 $$
说明：占用高度包含 1行顶部标题栏 + 2条分割线 + 1行底部状态栏

#### 代码强制边界约束
严格限制输入框内嵌补全菜单最大展示行数，超出行数自动内部滚动，从根源锁死渲染边界：
```java
// 补全菜单最多渲染3行，超出滚动，杜绝界面整体上移溢出
reader.setVariable(LineReader.LIST_MAX, 3);
reader.setVariable(LineReader.MENU_COMPLETE, true);
```

### 2. 零抖动精准刷新方案（并发日志托管）
业务场景：后台 `[O Observe]` 异步输出大量 Gradle 编译日志，同时用户可持续在中间输入框交互打字，全程无闪烁、光标不丢失。
底层方案：基于 **JLine 3 原生双缓冲打印机制** 实现日志分流渲染。

1. **日志输出规范**
    禁止直接调用 `System.out.println()`；所有TAO业务日志统一由独立后台线程捕获，通过 `reader.printAbove(logLine)` 输出。
2. **底层渲染原理**
    `printAbove` 内置ANSI控制码渲染流程：
    ① 擦除输入框下方全部渲染区域
    ② 追加打印新日志并完成滚动
    ③ 在原始坐标完整重绘输入框、补全下拉菜单，保证交互上下文不丢失

### 3. 状态栏全局绝对物理定位
底部计费、推理速率仪表盘由全局单例变量驱动，高频实时更新，需单行覆盖渲染避免全屏重绘开销。

#### 定位控制逻辑
扣费/推理状态更新触发时，通过两套ANSI序列实现精准单行刷新：
1. `\033[7;0H`：光标移动至终端倒数第一行首列（行数随终端实时高度动态计算）
2. `\033[K`：清空当前光标至行尾原有内容，单行覆盖写入新状态文本

#### ANSI 256色视觉美化示例代码
通过分级色彩区分数值、分隔符、模型标识，弱化分隔符视觉权重：
```text
\033[38;5;214m💰 $0.041\033[0m \033[38;5;242m│\033[0m \033[38;5;75m📊 125 t/s\033[0m
```

## 💎 设计演进核心总结
1. **极致降低视觉噪音**
    摒弃简陋文本分隔符 `|` / `-`，使用标准Box-drawing制图字符 `─` / `│` 搭配分层ANSI色彩，界面质感对标专业IDE内置控制台，脱离简易脚本终端观感。

2. **终端空间完全可控**
    通过硬编码 `LIST_MAX` 限制补全菜单高度，彻底修复传统TUI经典缺陷：补全条目过多导致整屏界面向上偏移抖动。

3. **轻量化适配单人迭代开发**
    架构适配独立快速迭代开发流程，整套TUI渲染逻辑基于纯Java 25原生API实现，核心代码总量≤300行，后续迭代、缺陷维护成本极低。
