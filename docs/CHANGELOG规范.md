# 通用项目 Changelog.md 命名与编写规范

**description:** record your changes — 标准化记录项目迭代、功能更新、破坏性变更与Bug修复，保证版本日志可追溯、易阅读

**规范定位**：沿用主流开源项目日志风格，统一命名、结构、格式与细节标准，适用于各类自研项目、工具库、应用系统，无需绑定特定产品

# 一、文件命名规范

- **固定文件名**：**CHANGELOG.md**（全大写+下划线，行业通用标准，兼容性最强）

- 禁止变体：changelog.md、ChangeLog.md、change-log.md 等非标准写法

- 存放路径：项目根目录，与README.md、LICENSE、package.json等核心文件同级

# 二、版本命名规范

## 2.1 版本标题格式（二选一，项目内统一即可）

- **未发布版本**：固定标题为 **Unreleased**（一级标题，无日期，存放待上线变更）

- **日期版版本**：**yyyyMMdd** 纯数字格式（年份4位+月份2位+日期2位，一级标题，无前导空格/分隔符），示例：`20260315`，适合迭代快、按日期发版的自研项目

- **语义化版本**：**v主版本.次版本.修订号** 格式，示例：`v1.0.0`、`v2.1.3`，适合库、SDK、标准化软件

## 2.2 版本排序规则

- 顶部优先：Unreleased（待合并/待发布内容）

- 下方按**时间倒序**排列正式版本，最新版本紧随Unreleased之后

- 版本间用水平分隔线（`---`）分隔，提升视觉区分度，日期版本严格遵循**yyyyMMdd**格式书写

# 三、层级结构规范（固定模块）

每个版本内部，严格按照以下**二级标题+无序列表**结构编写，顺序固定不可调换，无内容可省略对应模块：

1. **Changes**：新增功能、功能优化、配置调整、文档更新、体验升级等正向迭代

2. **Breaking Changes**：破坏性变更（不兼容旧版本、需手动迁移、废弃功能、配置重构）

3. **Fixes**：Bug修复、漏洞修补、兼容性修复、异常处理、逻辑纠错、稳定性优化

> 💡 层级格式：一级标题 = 版本标题；二级标题 = Changes/Breaking Changes/Fixes；正文 = 无序列表条目

# 四、条目编写规范（核心格式）

## 4.1 通用格式模板

```plaintext
[模块/功能分类]: [变更描述，简洁客观+精准表意]。([关联PR/工单编号]) [致谢/备注信息]
```

## 4.2 细节编写规则

- **模块前缀**：用斜杠或短横线分隔子模块，精准定位变更范围，示例：
        

    - 前端/登录、后端/接口、CLI/命令、数据库/迁移、UI/交互

    - 要求：简洁易懂，贴合项目代码目录或业务模块划分

- **变更描述**：
        

    - 用陈述句、客观表述，清晰说明**做了什么、解决了什么问题、优化了什么场景**

    - 代码命令、配置项、变量、接口名用````行内代码包裹，突出关键参数

    - 统一使用英文标点，语句通顺无歧义，避免口语化表达

- **关联编号**：
        

    - 格式：`(#数字)`，多个编号用逗号分隔，示例：(#2024)、(#1001, #1002)

    - 无PR/工单可省略，修复Bug可标注 Fixes #xxxx 关联工单

- **额外备注**：内部项目可省略贡献者致谢，团队协作可标注负责人或相关说明

# 五、格式排版与细节规范

- **文件头部固定格式**：
        `---
description: record your changes
---

# Changelog`

- **代码样式**：命令、配置、变量、接口必须用行内代码包裹，禁止用粗体替代

- **列表格式**：统一用短横线 `-` 作为无序列表标记，每条独占一行，不嵌套多层列表

- **空行规则**：标题与列表、模块与模块之间保留1个空行，避免内容堆砌

- **特殊场景写法**：
        

    - 修复类：优先写“修复XX场景下XX异常”“解决XX兼容性问题”

    - 破坏性变更：明确标注“不兼容XX旧版本”“需执行XX迁移操作”

    - 依赖升级：标注升级前后版本，示例：升级axios依赖至 v1.7.1

# 六、自用项目合规示例

```plaintext
# Changelog

## Unreleased

### Changes

- 后端/网关：新增内存队列基础方法，优化休眠节点任务分发逻辑。(#2024)
- 构建/配置：忽略本地运行状态文件，避免Git仓库出现无关变更。

### Breaking Changes

- 定时任务/校验：收紧任务推送权限，新增修复命令处理历史数据迁移。(#2023)

### Fixes

- AI模型/文本：过滤模型内部控制符，避免特殊符号泄露至前端页面。(#2022)

## 20260308

### Changes

- CLI/备份：新增本地备份创建、校验命令，支持配置单独备份模式。(#2021)
- 交互/语音：新增语音静默超时配置，优化自动发送逻辑。

### Fixes

- 系统/启动：修复macOS开机自启权限异常，保证服务正常拉起。
```

**核心原则**：格式统一、信息完整、简洁易懂、便于团队协作和版本回溯，可根据项目规模灵活精简细节
