## 3. 重点问题深度说明（P0）

### F1 门面绕过契约直连内核（P0）

**事实**：`kernel-architecture.md §2 硬规则1` 规定 "`Facade → Agent → Kernel` 单向，Facade 永不 import L3"；`facade-cli/DESIGN.md` 与 `facade-rpc/DESIGN.md` 均重申"不依赖 core"。但：

```
alice-facade-cli/module-info.java:  requires core-agent, core-planner, guardrail, model, memory-vault, tool-gateway
alice-facade-tui/module-info.java:  requires core-agent, core-planner, guardrail, memory-vault
```

且直接 `import org.cland.alice.core.agent.Agent`、`...wal.WalSession`、`...result.StepResult`、`org.cland.alice.model.ModelProvider`、`org.cland.alice.memory.sop.SopRegistry`。**协议契约层（proto/runtime）被实质性绕过**，CLI/TUI 实际上各自扮演了 `L2 Agent + 组合根`。

**后果**：
1. M2「facade 契约迁移」无立足点——迁移前必须先拆掉这些直连；
2. `StepEvent`/`AgentCommand` 契约形同建议，CLI/TUI 各有一套事件/结果模型（`StepResult` vs `StepEvent`）；
3. 组合根分裂：`runtime` 有 `compose.AgentComposer`，但 CLI 的 `ExecutionCoordinator`、TUI 的 `AliceTuiLauncher` 也在自建 `AgentConfig`/WAL/供应商。

**建议（M2-S0）**：
- 把组合/装配全部收口到 `alice-agent-runtime`（或 `alice-bootstrap` 的 compose），facade 只持有 `AgentCommandDispatcher` + 订阅 `EventStream`；
- 加 **ArchUnit/Gradle 断言**：`alice-facade-*` 的 `requires` 不得出现 `alice-core-agent`/`alice-model`/`alice-memory-vault`（rpc 已合规，可作样板）；
- CLI/TUI 的 `StepResult` 渲染改读 `StepEvent`（proto 已有 `EventCodec`，`JsonOutputRenderer` 已部分接入 `EventCodec`，说明路径是通的）。

### F2 存在两套"事件/结果"模型（P0 同源）

proto 定义了 `StepEvent`（出方向唯一真源），但 CLI/TUI 仍消费 `core.agent.result.StepResult`。`JsonOutputRenderer` 虽引了 `EventCodec`，仍 import `StepResult`。契约层与实际呈现层没有闭合。合并进 F1 一起处理。
